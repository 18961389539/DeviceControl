# V0.4—V0.6 纯软件路线（不包含实体设备和板卡）

## V0.4 配置与治理

- 角色：操作员/调试工程师/管理员。后端必须验证访问权限，不能只禁用前端按钮。
- 会话：本机仿真账号及显式登录登出，未授权请求统一拒绝；避免将演示账号当成生产级身份方案。
- 命令审计：记录谁在何时发起什么动作、决策结果、关联 TraceId；分页查询和导出。
- 站点/配方版本：Draft → Validated → Published，内容哈希、差异对比、一键回滚；执行期间不能热切换。
- 仿真错误恢复：故障代码 → 故障原因 → 满足条件 → 操作确认 → 流程恢复。

## V0.5 执行引擎

- 资源控制：同一轴或气缸不可被两个流程分支同时写入；明确资源锁的顺序和释放规则。
- 运行状态：RunId / StepId / Attempt / Start-End / Outcome / CancelReason；重入与幂等校验。
- 条件、循环、并行和 Join 节点；先做模拟执行与静态冲突检查，再开放图形编辑。
- 节点级失败策略：Abort、Retry（仅幂等动作）、WaitForOperator、JumpToRecovery；提供可视化测试。

## V0.6 工程产品化

- SQLite 模型：周期、步骤、报警、命令、配置版本；明确迁移和清理策略。
- 可视化流程编辑与静态验证：悬空节点、循环边界、资源争抢、不可恢复分支等。
- 模拟设备脚本：场景录制/回放、压力测试、超时故障注入、验收报告。
- UI：报警定位、逐步骤诊断、运行趋势、配方差异、操作引导。

**本路线默认不引入任何真实设备接入工作。**
